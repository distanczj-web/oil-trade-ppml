# Additional reporting and prior-relationship checks

Run the repository-level `restore_data.py` before these checks. Frozen input records and model data retain their original values.

`audit_world_only.py` distinguishes positive World totals with no valid bilateral country-partner records from ordinary absent partner records. It verifies the partner classification against the frozen initial-panel country universe and compares the affected importer-years with the final Model D keys. The broader no-positive-bilateral check is reported separately.

`run_positive_relations.do` retains prior recorded import shares strictly above zero, uses standard ppmlhdfe to determine final finite support, and fits the same six-regressor model with standard and independent Stata/Mata implementations on that support. `audit_positive_relations.py` verifies unchanged keys, outcomes and regressors, coefficient/SE agreement, finite positive fitted values, local fixed-effect margins, normalised scores, and the covariance used for percentile comparisons.

The candidate count is 37,965; the final count is 36,362 observations for 1,669 directed country pairs. The source share is retained without renormalisation. Percentiles in the positive-only comparison are calculated on its final support, separately from the original full-sample percentiles. This is conditional heterogeneity, not a causal mechanism test.

All `.dta` files produced under `outputs` are regenerated by the Stata command. The supplied CSV/GZIP outputs, run log and audit JSON files record the frozen results. Run verification on the supplied release before estimation, and perform reruns in a working copy because scripts replace outputs.
